# Combat Implementation Plan (Plan 5 of 7)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Simple D&D combat resolved by scripts (dice, HP, AC, turns), NPC warnings before a fight, fights that can sit inside a quest, and "advanced moves" that need the player to solve a Master-written JS problem.

**Architecture:** Pure combat math in `game/combat.js`. A fight engine stores state in SQLite and rolls every die through `game/dice.js`. Advanced-move problems are tests the Master supplies; a script validates them against the Master's reference solution, then runs the player's file in a child process like quests do.

**Tech Stack:** Node.js (`node:sqlite`, `node:test`, `node:child_process`), SQLite.

**Spec:** `docs/superpowers/specs/2026-11-07-js-dnd-campaign-design.md` (5.7; 5.6 for kill honor). Builds on Plans 2 to 4: `game/fights.js`, `game/rolls.js`, `game/hero.js`, `game/world.js`, `game/quest-runner.js`.

## Global Constraints

- No em-dash (U+2014) or en-dash (U+2013) anywhere. Build them with `String.fromCharCode` in tests.
- Commit and push after each task with plain messages. Never a Co-Authored-By or Claude line. Never force-push without asking.
- Game state only in SQLite through scripts. Every dice roll comes from `game/dice.js` via the scripts; the AI never invents a roll.
- Every connection uses `openGameDb`. Script output is one line of JSON; errors are JSON on stderr with exit 1; tamper exits 2. Each command accepts only its own options and rejects extra arguments.
- Combat uses D&D-style rules; ordinary combat is not JS code. Only advanced moves trigger a JS problem, written and judged by the Master (spec 5.7).

## Decisions

Approved by the owner:
- **Simple core:** initiative from DEX, HP, AC, attack roll vs AC, damage dice. No spells or inventory yet.
- **Advanced move:** solving its JS problem means a sure hit with double damage. Failing it means the turn is lost, nothing else.
- **Defeat:** at 0 HP the hero is knocked out and wakes at `L1`. The fight is logged as lost. No permadeath.

Calls made while planning (the owner can reject any):
- Ability modifier is `floor((score - 10) / 2)` using base plus race bonus. Hero max HP is `10 + CON mod`. AC is `10 + DEX mod`. Attack bonus is the better of STR and DEX mod plus 2. Damage is `1d8` plus that same mod (minimum 1).
- NPC tiers: `weak` (6 HP, AC 10, +2, 1d4), `normal` (14 HP, AC 12, +3, 1d6), `tough` (26 HP, AC 14, +4, 1d8). The Master picks the tier.
- One enemy per fight. HP resets to full at the start of every fight (no healing system yet).
- Initiative is `1d20 + DEX mod` for both sides; ties go to the hero. A natural 20 always hits and doubles the damage dice; a natural 1 always misses.
- One `fight attack` command is a hero turn followed by the enemy's response. If the enemy won initiative, its first turn happens inside `fight begin`.
- Winning a fight is a kill. Honor is applied by script: `kill_self_defense` (no change) if the enemy was the aggressor, `kill_unprovoked` if the hero was. Fleeing and defeat change no honor.
- An NPC may only start a fight after two warnings (`npc warn` returns `mayFight` true from the third provocation). A quest-embedded fight (`--quest`) needs no warnings.
- Combat functions accept an optional `modifiers` object so Plan 6 can pass tiredness penalties.
- A tamper reset abandons any open fight.
- Advanced-move problems need 3 to 12 test cases, a reference solution that passes all of them, and a solution function named `solve`. Tests stay hidden from the player (stored in the DB).
- The old low-level `fight start`, `fight log`, `fight end` commands from Plan 2 stay for logging but are no longer used by `/play`.

## Review Focus

1. Combat math boundaries: modifiers at 8, 9, 10, 11, and 20; natural 1 and natural 20; damage never below 1 (Task 1).
2. Fight state: no action after the fight ends, no two open fights, HP never negative, flee and defeat reset correctly, honor follows the aggressor (Task 2).
3. Warnings count per NPC and per save, and gate NPC-started fights except quest fights (Task 2).
4. Bad move problems (unsolvable, too few tests, wrong shape, looping reference) are rejected; a player file that loops, throws, or exits loses the turn and never hangs the CLI (Tasks 3, 4).
5. A tamper reset abandons an open fight and the scripts refuse to act on it (Tasks 2, 5).

### Task 2: Fight engine and warnings

**Files:** Modify `game/schema.js` (migration 6, the `fights` columns and `npc_warnings`), `game/reset.js`; Create `game/combat-engine.js`, `tests/game/combat-engine.test.js`

**Interfaces:**
- Consumes: Task 1, Plan 2 `fights.js`, Plan 4 `world.js`/`hero.js`.
- Produces:
  - `warnNpc(db, saveId, npcSlot: string, reason: string): { warnings: number, mayFight: boolean }` (`mayFight` is true once the count reaches 3).
  - `beginFight(db, saveId, { npcSlot, tier, aggressor: 'hero'|'npc', questId?, rng? }): FightState`. Requires a hero, a complete world, and the NPC at the hero's location. An NPC aggressor needs `mayFight` unless `questId` is set. Rolls initiative; if the enemy goes first, resolves its first turn.
  - `heroAttack(db, saveId, { rng?, doubleDamage?: boolean, sureHit?: boolean }): FightState` (hero turn then enemy response).
  - `fleeFight(db, saveId): FightState` (ends as `fled`).
  - `getFightState(db, saveId): FightState | null` for the open fight.
  - `FightState = { fightId, round, hero: { hp, hpMax }, enemy: { name, tier, hp, hpMax, ac }, log: LastSteps[], status: 'open'|'won'|'lost'|'fled', honor?: number }`.
  - On win: apply `kill_self_defense` or `kill_unprovoked`. On defeat: end `lost`, hero to `L1`. A tamper reset marks open fights `abandoned`.

- [ ] **Step 1: Write the failing tests** (injected rng): warnings count per NPC and per save and `mayFight` from the third; `beginFight` rejects no hero, incomplete world, NPC elsewhere, a second open fight, an NPC aggressor without enough warnings, but allows it with `questId`; initiative order decides who acts first and ties go to the hero; a hit lowers enemy HP and logs rolls and steps with gapless seq; a miss does not; enemy response happens after a hero turn when the enemy lives; HP never goes below 0; win ends the fight, kills the enemy, and applies the honor rule by aggressor; defeat sets the hero at `L1`, status `lost`, and no honor change; `fleeFight` ends `fled`; no action on an ended fight; a tamper reset abandons the open fight.

### Task 3: Move problem runner

**Files:** Create `quests/run-tests.js`, `game/move-runner.js`, `tests/game/move-runner.test.js`

**Interfaces:**
- Produces: `runMoveTests(playerPath: string, tests: { args: unknown[], expected: unknown }[], opts?: { timeoutMs?: number }): { status: 'pass'|'fail'|'error'|'timeout', expected: string, got: string, message: string }` (same shape and hardening as `runQuestCheck`: child process, random result token, clipped text, never throws).
